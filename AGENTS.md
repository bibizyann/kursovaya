# Project guidance

## Purpose

This repository contains the practical implementation for the graduation project described in `Диплом.md` and planned in `План.md`. The system manages software lifecycle for distributed factory edge nodes using Kubernetes operators and GitOps.

## Language and style

- Go is the primary implementation language.
- Keep the project as one Go module until a concrete reason to split it appears.
- Use standard-library packages where they are sufficient.
- Keep domain logic independent from Kubernetes clients so it can be unit tested.
- Run `gofmt` on all changed Go files.
- Public Go identifiers require concise English doc comments.
- Operational messages, metric names, API fields, and source-code comments are written in English. User-facing documentation may be in Russian.

## Architecture boundaries

- Git is the target source of desired production state.
- Argo CD owns Git-managed `TechProcess` and `TechProcessTemplate` resources.
- The operator owns resources derived from those CRs. Do not let Argo CD and the operator mutate the same fields or child workloads.
- Kubernetes desired state is the command channel for process changes.
- MQTT is for production telemetry, not an alternative desired-state channel.
- gRPC is reserved for local edge-agent and equipment interactions.
- The edge agent handles hardware access, calibration, last-known-good hardware configuration, and store-and-forward telemetry. It must not duplicate kubelet or KubeEdge metadata synchronization.
- Hardware-bound workloads are scheduled by capability labels. Never assume an arbitrary node can replace a failed hardware node.
- Exclusive hardware workloads use a safe `Recreate` or staged rollout; do not run two drivers against one device.
- The local factory cluster remains authoritative for the critical path. Cloud integrations are optional and must not be required for production continuity.

## Kubernetes API rules

- APIs start at `production.factory.local/v1alpha1`.
- Prefer selectors and required capabilities over literal node-name lists.
- Status must use `observedGeneration` and `metav1.Condition`.
- Reconcile functions must be idempotent and safe after controller restart.
- Child resources require owner references and deterministic names.
- Deletion requiring hardware shutdown must use a finalizer.
- A process cannot become Ready until Kubernetes workloads, equipment health, and calibration are all ready for the same revision.

## Validation

Before handing off changes, run the narrowest applicable commands, then the full project checks when practical:

```bash
make fmt
make test
make vet
```

Use `make test` when CRDs or controllers change and `make test-e2e` when deployment behavior changes.

## Generated files

- Kubebuilder-generated files under `config/` and `zz_generated.*.go` may be regenerated by project tools.
- Do not manually edit generated deepcopy code.
- Keep generated CRDs and RBAC synchronized with Go API markers.

## Documentation

- Record material architecture choices in `docs/adr/`.
- Add or update a nearby `AGENTS.md` when a subsystem gains conventions that are not obvious from this root file.
- Keep runbooks reproducible and avoid commands that depend on undocumented local state.
